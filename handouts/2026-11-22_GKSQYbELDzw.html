What Runs Where? Local AI in Production — Ahmad Osman, Osmantic

AI Engineer · 56 min talk · Watch · Transcript · 2026-11-23 01:33 UTC · gemini-3.6-flash

Local models are now good enough that placement — matching each step's difficulty to the right model, memory system and engine — is the production work, not chasing the frontier.

TL;DR

  • Frontier intelligence is needed only where the step is hard; small specialized models carry the rest.
  • A local workstation beat a frontier cloud API on latency in a blind test.
  • Identical open weights score differently by serving host; benchmark the endpoint, not the name.
  • A GPU costs the same busy or idle; utilization sets self-hosted token economics.

Workshop by Ahmad M. Osman, founder and CEO of Osmantic, at the AI Engineer Code Summit, San Francisco, November 10, 2026. Evidence mixes ODS's own measurements, OpenRouter telemetry, public leaderboards, and papers or vendor write-ups days to weeks old at delivery. Osmantic sells optimized local inference engines and an agent harness, so the small-specialized-model thesis is commercially aligned. The speaker warns the answer shifts every few months.

Deep dives

[18:57] Prefill and decode want different hardware

  • Long prompts raise first-token wait; long answers raise total time. Measure the user's wait and the system's throughput separately; under load they move apart.
  • 2x DGX Spark prefilled DeepSeek V4 Flash at 1,600 vs M5 Ultra's 748 tok/s; M5 Ultra decoded 6% faster.

Why it matters: Match hardware to the workload's prompt-to-answer mix.

Watch out: Single-request speed does not predict batched serving; differing stacks and quant formats confound box-to-box comparisons.

[15:46] Bits decide what fits; QAT limits the loss

  • QAT trains with the rounding in the loop; weights were chosen knowing they would be rounded. The converted file serves on existing PTQ kernels, format unchanged.
  • Dynamic quantization degrades unevenly: GLM-5.3 scored 94.3% full, 88.5% at 3-bit, 21.7% at 1-bit.
  • DeepSeek V3.1 lost 0.5 points at 3-bit but 18.3 at 1-bit.

Why it matters: Quantization's fit-versus-accuracy trade is model-specific and must be measured per candidate.

Watch out: 1- and 2-bit compression can collapse quality; per-model results do not transfer.

[29:31] Save inference state where turns end

  • vLLM saves state at 4,352-token block boundaries, never at a turn's end; the gap between the last saved state and turn end is prefill you pay again.
  • FlashStates saves a state exactly where each turn ends.
  • Three hybrid models: GLM-5.3-Flash 3.14x prefix tok/min and -96% p50 TTFT; Nemotron 3 Super 2.27x, -97%; Qwen3.8-Flash-Next 1.54x, -66%.

Why it matters: Turn-end state saving removes repeated prefill from agent context resends.

Watch out: Gains ranged 1.54x to 3.14x by model; the paper was published days before the talk.

[32:14] The harness, not a bigger model, fixed the failure

  • Qwen 3.5 27B with Claude Code failed to change an RTX 5090's RGB lights; adding a search engine fixed it.
  • Exo: the agent edits its harness — tools, prompts, context rules, memory — never the weights; run history is append-only with rollback.
  • Held-out work: 35-61% lower model cost on repeated tasks; kept decisions became code; novel work still needs fresh reasoning.

Why it matters: Fix the harness before buying a bigger model.

Watch out: Offline agents fail on post-cutoff knowledge; self-edited harnesses need code-change gating.

Field playbook (inferred from the talk, not claims made in it)

Ask the customer

  • Which steps genuinely need frontier reasoning, and which are routing, classification or formatting?
  • What request rate and GPU duty cycle would make owned hardware break even with current API spend?
  • What share of tokens is agent-resend context that caching or state reuse could remove?

Measure in a pilot

  • First-token wait and decode speed at target concurrency, on the exact production endpoint.
  • Held-out task quality for identical weights across candidate hosts and engines.
  • Total cost per completed task, retries included, at measured utilization versus the incumbent API.

Where it breaks

  • A box fast for one user collapses under bursty concurrency if the stack cannot batch.
  • A bigger model gets bought when the real gap is a missing tool or stale knowledge.
  • Silent failures: a script prints done after a step dies; nobody checks the artifact.

What the talk does not establish

  • The blind test is one user, one question; no multi-user or long-session comparison shown.
  • The Airbnb result covers one classifier; small fine-tuned models are not shown generalizing across tasks.
  • Break-even math omits maintenance, failure and operations costs; utilization is assumed, not measured.
  • FlashStates, Exo and the audit rerun had no third-party replication at delivery.

Checklist

  • Profile one real request end-to-end before paying for any single-component speedup. [28:29]
  • Split the pipeline: assign frontier models only where the step is hard. [10:30]
  • Choose hardware, workload shape and serving model before picking an inference engine. [26:40]
  • Benchmark identical open weights on each candidate host endpoint before committing. [27:15]
  • Compute the GPU duty-cycle break-even against the API price actually paid. [42:20]
  • Run learned changes through Log, Curate, Adapt, Gate, Promote with versions and rollback. [54:35]

Terms as used in the talk

Prefill
Compute-bound phase that reads the prompt; dominates first-token wait on long prompts.
Decode
Memory-bandwidth-bound phase that writes output tokens; dominates total time on long answers.
Time to first token
User's initial wait: queue, scheduling and prefill combined.
Quantization
Lowering weight precision to fit smaller memory; QAT bakes it into training, PTQ applies it after.
