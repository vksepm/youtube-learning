How to build an agent that builds the culture — Zach Bruggeman, Ramp

AI Engineer · 14 min talk · Watch · Transcript · 2026-11-23 02:05 UTC · gemini-3.5-flash-lite

A shared, public-by-default coding agent becomes cultural infrastructure: one baseline everyone inherits, so trust and best practices compound through visible sessions instead of siloed individual setups.

TL;DR

  • Around 75% of Ramp's code is written and shipped by Inspect with no usage mandate — a shared baseline plus public sessions made adoption self-sustaining.
  • Kill information silos: one Inspect for the whole company; improvements push to everyone immediately and invisibly, removing repeated per-person setup.
  • Build trust through artifacts: reviewers see the full session — conversation, tools, screenshots, verification video — not just a 400-line diff.
  • Think bigger together: engineers built Review Buddy on existing automation triggers without permission, turning Inspect from a coding agent into culture.

Zach Bruggeman, an engineer at Ramp, presents a practitioner account of Inspect, Ramp's collaborative coding agent, after roughly a year of internal adoption. The evidence is single-company and self-reported; technical plumbing is deferred to Ramp's blog and a Pragmatic Engineer deep dive. No methodology is given for its headline figure. Scope is culture and org lessons, not engineering internals; Inspect is now a market product (inspect.com/AIE).

Deep dives

[02:11] Lesson 1 - Kill information silos

  • One shared Inspect serves the whole company; any improvement or new tool is pushed to everyone immediately, and most changes are invisible to users.
  • Because a solid baseline always exists, usage never had to be mandated — people stop reaching for private setups.
  • Sessions are public by default, so teammates learn by watching and can ask Inspect to summarize recent sessions, prompts, and problem breakdowns.

Why it matters: Centralizing agent configuration removes per-person setup drift and makes best-practice updates zero-friction; public sessions turn tacit workflow knowledge into a searchable, observable corpus. (inference)

Watch out: A single shared default can lag niche teams; public-by-default sessions risk exposing secrets or unreviewed work if scopes aren't controlled.

[05:20] Lesson 2 - Build trust through artifacts

  • Trust in agents is transferred socially — people learn to trust what an agent builds by watching others, not through formal training.
  • Every shipped change links to a living session artifact: full conversation, tools used, screenshots, and a video of the verification agent clicking through the app.
  • In the Andrew bug thread, skeptical participants worked in public, prodded the agent, and turned into collaborators within an hour.

Why it matters: Making agent reasoning auditable in the PR converts trust from a personal leap into an inspectable, shareable record — a governance lever for enterprise adoption. (inference)

Watch out: Transparency cuts both ways: the same thread exposed the team's own skepticism and a near-switch to Claude Code.

[10:00] Lesson 3 - Think bigger together

  • Reverence for the lone-wolf operator risks collapse if builders treat only themselves as the audience and stop sharing.
  • Review Buddy was built by two engineers using Inspect's existing automation triggers — including a fired-on-open pull request — without asking permission.
  • User-built agents pushed Inspect's own team to think beyond 'just a coding agent' toward a fuller loop.

Why it matters: Platforms compound when users extend them unsolicited; designing exposed triggers and primitives is what lets bottom-up innovation surface. (inference)

Watch out: Not every iteration worked; a platform that invites user-built agents must still govern quality without killing initiative.

[00:30] Prompt-to-ship surface and integrations

  • Inspect works alongside the team across Inspect, Slack, Linear, and other integrations.
  • Design primitives, review agents, and verification flows let any builder go from prompt to shipping on Inspect.
  • Company-wide integrations connect everyone to telemetry, databases, and other tooling automatically.

Why it matters: The surface, not just the model, is the product: shared integrations and review/verification stages embed governance into the workflow rather than bolting it on. (inference)

Field playbook (inferred from the talk, not claims made in it)

Ask the customer

  • Where does agent best practice live today — a shared platform default or scattered individual setups that drift?
  • What would make an agent session a first-class, reviewable artifact inside your existing PR and review workflow?
  • Which workflows are stuck behind permission requests that users would build themselves if the platform exposed triggers?
  • What definition of code written or shipped by agents would your team trust enough to act on?

Measure in a pilot

  • Adoption without mandate: share of engineers using the shared baseline rather than private tools after rollout.
  • Knowledge spread: fraction of sessions public and consumed by teammates, as a proxy for silo elimination.
  • Debug speed: time from bug report to fixed change when the thread runs in public versus private.

Where it breaks

  • Public-by-default sessions leak secrets or unreviewed code when integration scopes are not locked down.
  • The single shared agent lags fast-moving teams, who quietly revert to private tools like Claude Code.
  • One visible bad agent change erodes trust company-wide because all work happens in the open.

What the talk does not establish

  • No methodology behind the 75% figure: what counts as code, over what window, and how it's attributed.
  • No measured before/after on setup cost or divergent outcomes — only illustrative 15-minute arithmetic.
  • All evidence is single-company and self-reported by the vendor; no independent or external validation.
  • No failure-rate data: how often agent changes break, get reverted, or push users to private tools.

Checklist

  • Ask the platform owner for the exact definition, window, and attribution behind the 75% code-written figure. [01:00]
  • Wire agent sessions into the PR view so conversation, tools, and verification evidence are reviewable artifacts. [06:30]
  • Pilot one shared agent baseline and measure adoption before considering any usage mandate. [03:20]
  • Expose automation triggers such as pull-request-opened so teams can build agents without permission. [11:50]
  • Instrument the agent itself and resolve one real bug end-to-end in a public thread. [07:10]
  • Run a week where each team lists what they have been waiting to build, then build one item together. [13:00]
