How to Ship Millions of Lines of Agent-Written Code — Jarred Sumner, Anthropic

How do you trust millions of lines of agent-written code? Design testability in first: pre-existing suites, three-way differential runs, and fuzzers the model cannot game.

TL;DR

  • Bun's ahead-of-time compiler — 28,547 agents, five rewrites, 46 days — was trusted via test suites predating the project.
  • bun compile starts Claude Code 2.2x faster with 4.4x less memory; cloud sessions stop recompiling identical code.
  • Verification is layered and hard to game: three-way CI runs, pre-existing suites under bun test --aot, fuzzers checked against known-wrong programs.
  • The human mostly monitored: top prompts were continue (34x) and hows (32x) among about 5,500 messages.

Presented at AI Engineer by Jarred Sumner, Bun's creator, now at Anthropic. Case study: an ahead-of-time compiler for Bun, motivated by cloud sessions recompiling identical code and by JIT overhead — type-checking Effect with TypeScript 6 spends 47% of CPU time compiling in Bun's JIT (MacBook Pro). Evidence: the project's own scorecards, parity tables, and terminal logs, Sep 27-Nov 10; single operator, development builds.

Deep dives

[04:15] Design for testability from the start

  • Bun's tests spawn the bun binary; the same suite verified the Zig-to-Rust move in 11 days, zero skipped.
  • Claude Code's tests import source modules; port them and 'you can't really trust the tests anymore.'
  • CI runs 18,454 programs per pull request three ways — JIT, compiled, compiled without types — outputs must match.

Why it matters: Implementation-independent verification lets agents attempt rewrites; suites coupled to source block ports and reward gaming. (inference)

Watch out: New tests written during a port cannot referee that same port.

[14:10] Rewrite instead of refactor

  • Compiler 4 iterated flow analysis until nothing changed; good code, but compiles too slow.
  • Compiler 5 visits everything once — Scan, Link, Walk, Codegen; internal build 79 s to 17 s, 16 cores, no cache.
  • Speedups came from deleting code and work, not sizing up compiler passes.

Why it matters: Agents make full rewrites cheap enough to treat architecture as expendable; compounding-cost designs get replaced, not tuned. (inference)

Watch out: Public-build compiles ranged 33-283 s (Oct 19-Nov 1); the slowdown failed no tests.

[12:19] Three modes of working

  • One night: design docs, design review, 140 agents each writing one file, adversarial review — 400,000 lines — then build and run.
  • Work moved from step-by-step workflows to long-lived subagents, one per idea, for days.
  • An hourly Slack scorecard of prioritized metrics tracked progress via a /loop 1h command.

Why it matters: Batch-then-verify with an hourly scorecard substitutes for continuous human supervision of long-running agents. (inference)

Watch out: Planning overproduces markdown; one plan projected about 7,600 files — '1500 markdown files is insane slop.'

[06:19] Types as predictions

  • Types are predictions: double(JSON.parse('3')) prints '33' identically under Node.js and bun compile.
  • Property access compiles in tiers: proven-monomorphic loads directly; maybe-null adds a check; unknown looks up by name.
  • Slide lists tier costs 12,160, 10,568, 33,554 — units unclear in transcript.

Why it matters: Keep TypeScript, skip the Rust rewrite; polymorphic or JSON-heavy call sites keep dictionary-lookup costs. (inference)

Watch out: eval and new Function run slower; Object.prototype modification is banned; interpreter-heavy tools regressed — UglifyJS 2.5x slower than Node.js.

Field playbook (inferred from the talk, not claims made in it)

Ask the customer

  • Which existing test suites pass today, and do any import implementation internals?
  • What compile-time or build-time budget exists per change, and who enforces it?
  • Which workloads lean on eval, new Function, or Object.prototype mutation?

Measure in a pilot

  • Startup time and memory at the prompt, JIT versus compiled, on target hardware.
  • Pre-existing suite parity: same-result, refused, and different counts per suite.
  • Compile and build time per change, alerted even while tests stay green.

Where it breaks

  • Porting the test suite together with the code destroys the independent referee.
  • Planning stages flood the repository with markdown and design-slop artifacts.
  • Interpreter-heavy or eval-heavy workloads regress; unmeasured metrics drift silently.

What the talk does not establish

  • No token, compute, or cost figures for the agent runs behind the project.
  • Benchmarks are self-reported, single-machine, development builds; no external reproduction.
  • One operator, one codebase; team-scale and cross-project generalization untested.

Checklist

  • Run bun upgrade --canary then bun compile app.ts on a representative workload; ships in Bun 1.5. [22:00]
  • Inventory existing test suites; flag tests that import implementation internals. [04:42]
  • Stand up three-way differential CI: JIT, compiled, compiled-without-types outputs must match. [08:14]
  • Post an hourly metrics scorecard to a shared channel during agent builds. [16:35]
  • Seed fuzzing from programs the system gets wrong; verify the fuzzer catches them. [17:46]
  • Alert on compile-time and build-time regressions even when tests pass. [13:06]
