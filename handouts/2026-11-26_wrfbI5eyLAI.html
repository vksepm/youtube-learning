TL;DR

  • A 1,000-agent Fable 5.2 team formalized Fermat's Last Theorem with a minimal harness and no human steering, using only Git and a database.
  • The lead agent created its own coordination tables unprompted; agent teams can now self-orchestrate very long-horizon work.
  • Offline 'dreaming' passes repair poison memories and compile transcripts into wikis, improving on search alone.
  • Memory-store value is model-dependent: older Sonnet 4.6 gains almost nothing, newer Opus models gain substantially.

Lance Martin (Member of Technical Staff, Anthropic) presented two Anthropic blog results at the AI Engineer Code Summit: a large-agent-team formalization of Fermat's Last Theorem, and agent memory with offline consolidation. All evidence is Anthropic-produced: single runs, Anthropic-run benchmarks, and one eval on the anonymized corpus of Stainless, a company acquired in May; CL-Bench itself is open-source. Deep dives

[03:00] Harness: 1,000 sandboxes, one gateway, two primitives

  • Each of 1,000 agents runs in its own sandbox: no internet, no shared filesystem, no direct paths between sandboxes.
  • Agents reach only two primitives, Git and a Postgres database; a gateway authenticates, logs, and inspects every request, never trusting agents.
  • Offline monitoring runs sensors every 10 minutes, reads Postgres and Git, and blocks a sandbox if needed.

Why it matters: One auditable egress choke point is what makes a thousand-agent fleet governable; the same shape transfers to any enterprise agent deployment. (inference)

Watch out: Gateway overhead at 1,000x scale, latency and cost of inspecting every call, is unquantified.

[03:57] Agent-authored coordination schema

  • Prompting set one lead, 999 helpers, awareness of Git, the database, and the problem statement, nothing more.
  • Five minutes in, the lead created five coordination tables, Announce, Assign, Notes, Subtasks, Landed, with no instruction to.

Why it matters: Orchestration schema can be agent-authored; harness engineering shifts to providing state storage and safety, not workflow code. (inference)

Watch out: Single run; schema quality and generality across tasks or models untested.

[12:50] Dreaming: offline memory consolidation and repair

  • Agents write memory myopically during tasks, but memory must be globally coherent and non-redundant, a fundamental paradox.
  • Dreaming compiles transcripts and notes into representations like wikis and promotes memories into injected context loaded into every session.
  • A wrong landmark note trapped Pokémon gameplay in a loop; an offline pass corrected the note and the run reached Cerulean at action 1930.

Why it matters: Design implication for any long-lived agent memory: separate live capture from an offline audit and repair pass, or poison notes persist. (inference)

Watch out: Rescue evidence is one gameplay anecdote, not a controlled experiment.

[15:26] Wiki quality scales with dreaming compute

  • Eval: 25 questions answerable only from the anonymized Stainless corpus.
  • Search alone scores 53%; wiki alone rises 16% to 48%; wiki plus search 54% to 61% as dreaming tokens scale 1M to 12M.
  • Wiki grew from 103 pages and 764 links after 2 sessions to 323 pages and 12,893 links after 128.

Why it matters: Dreaming tokens are a tunable quality-versus-cost knob for knowledge representations, and learned wikis compose with retrieval rather than replace it. (inference)

Watch out: Log-scale token axis is budget, not spend; one corpus, 25 graded questions.

Field playbook (inferred from the talk, not claims made in it)

Ask the customer

  • Which of your long-horizon tasks could run on shared state primitives, a repo and a database, instead of a bespoke harness?
  • What is your agent fleet's egress surface today, and could every request pass one auditable gateway?
  • Who audits your agents' stored memories, and what happens when one is wrong?

Measure in a pilot

  • Statements or subtasks completed per hour, plus share of helpers idle or sync-blocked, from shared-state logs.
  • Task score with versus without a memory store on your target model, with no memory prompting.
  • Errors corrected per offline dreaming pass, per million tokens spent.

Where it breaks

  • Mid-run state loss: agents stop collaborating when no harness keeps project state visible.
  • Poison memory: one wrong note loops agents until an offline repair pass runs.
  • Gateway bottleneck: inspecting every call from 1,000 sandboxes may cap throughput or inflate cost.

What the talk does not establish

  • No cost, token, or compute totals for the 1,000-agent run; economics are unquantified.
  • Single run reported; no repetition, variance, or cross-model comparison of the formalization result.
  • Slides never show the 1,000-agent run completing all 60 statements; completion rests on the speaker's summary.
  • Wiki eval covers one anonymized company corpus and 25 questions; generalization untested.

Checklist

  • Give a multi-agent pilot only Git and a database as shared primitives; log what coordination schema the agents build themselves. [03:57]
  • Route all sandbox egress through a gateway that authenticates, logs, and inspects every request for misuse. [03:00]
  • Schedule offline monitoring over shared state at a fixed interval, with defined sandbox-block triggers. [03:24]
  • Benchmark your target model with versus without a memory store before building any memory tooling. [09:40]
  • Add an offline pass over transcripts and notes; count poison memories corrected per pass. [14:32]
